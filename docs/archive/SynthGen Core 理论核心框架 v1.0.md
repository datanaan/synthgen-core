SynthGen Core 理论核心框架 v1.0
—— 附工程可行性审视与风险备案
文档状态：核心理论定稿，附工程可行性评估
定稿日期：2026-05-08

一、系统定位
SynthGen Core 是一个面向物理世界的智能合成数据生成器。其根本使命：

在用户给定的数据世界框架内，生成其可能存在样貌的多样性。

工程可行性：此定位可行。它不要求突破任何未解决的基础研究问题。核心任务——在给定分布假设和物理约束下生成数据——在GAN/VAE/扩散模型的现有能力范围内。

风险备案：无。定位本身是最低风险的部分。

二、核心矛盾与对称解
核心矛盾：数据生成器无法自证其所生成数据的最终可信性。

解矛盾：引入独立的外部验证端。SynthGen Core 只制造候选证据，可信性由验证端赋予。

工程可行性：可行。这是一种架构解耦，不是算法问题。实现代价为零（不增加代码），但要求产品文档明确传达这一边界。

备选路径：如果外部验证端不可用，系统回退为纯工具模式，用户通过自身测试间接验证。此回退路径天然存在，不需要额外开发。

三、三大能力支柱
3.1 物理驱动
理论：在约束卡片定义的合法空间内生成数据点。

工程可行性：有条件可行。

✅ 约束卡片是领域专家可编写的，格式为声明式的规则（如 风速 ∈ [0, 25] m/s）。

⚠️ 风险：约束卡片的编写需要领域专家。如果没有专家，此支柱退化。这是社会工程约束，不是技术约束。

⚠️ 风险：约束卡片可能存在遗漏或内部冲突。系统需要冲突检测和缺失告警。

备选路径：

若无领域专家：使用统计方法从数据中估计值域（如 [min(data)*0.8, max(data)*1.2]），但明确标记为“统计推断边界，非物理边界”。

若约束卡片冲突：系统应检测并报告，允许用户手动解决，拒绝在冲突约束下生成。

能力漂移：若物理驱动完全不可用，系统退化到纯数据驱动模式，失去物理合法性保证，但仍保统计逼真性和可追溯性。

3.2 数据驱动（模仿）
理论：从真实数据中学习分布，生成统计上相似的数据。

工程可行性：有条件可行。

✅ 对于结构化时序数据，GAN/VAE/扩散模型已在多个工业领域验证。

⚠️ 风险：小样本问题。当真实数据少于几百条时，生成质量急剧下降（模式坍缩、方差坍缩）。

⚠️ 风险：高维稀疏数据。用户输入维度很多，但每个维度的有效样本很少。

备选路径：

小样本：退化为基于KDE的扰动生成（对历史数据点加噪声），比神经网络粗糙但不会坍缩。

高维稀疏：先做维度重要性筛选或主成分分析，在低维隐空间生成，再映射回原始维度。

极端情况：回退为纯物理驱动（见失败模式三）。

能力漂移：若数据驱动不可用，系统失去统计逼真性，但仍保证物理合法性和可追溯性。

3.3 约束驱动（融合）
理论：在数据驱动生成过程中嵌入物理约束，实现受控的逼真性。

工程可行性：高风险，需分阶段实施。

✅ 最简方案（后筛选）可行：先用纯数据驱动生成，再用约束卡片过滤。实现简单，问题在于生成效率可能很低（如果大部分生成样本被滤掉）。

⚠️ 进阶方案（损失函数约束）：PINN-GAN等方法在理论上可行，但训练极不稳定，超参数极度敏感。这仍是活跃研究领域，不是成熟工程。

⚠️ 架构嵌入方案：修改网络结构以强制满足约束（如输出层加软约束层），对每类约束需要单独设计，通用性差。

备选路径（按优先级）：

第一阶段（安全）：后筛选。投入低，效果确定，作为基线。

第二阶段（进阶）：损失函数正则化。仅在特定DomainPack下调试，不作为通用方案。

第三阶段（远期）：架构嵌入。在研究成熟后，作为可插拔的优化器。

能力漂移：若约束驱动的进阶方案不可行，系统保留物理驱动+后筛选的基线组合，能力不丢失，但生成效率可能打折扣（需过量生成再过滤）。

四、输入诚实性原则
理论：输出严格忠实于用户输入定义的三重基准（格式、维度、可行性暗示）。

工程可行性：完全可行。

✅ 格式校验：通过输入数据的Schema验证输出格式，纯工程问题，零风险。

✅ 维度校验：输出维度集合与输入维度的匹配检查，纯工程问题。

⚠️ “可行性暗示”的检测较模糊——用户输入的值域和统计特征可以在生成前提取并设定为软约束，但无法捕获隐含的因果结构。

备选路径：如果可行性暗示检测不完善，系统应显式声明哪些维度受到了输入数据的值域约束，哪些没有，让用户自行判断。

能力漂移：无严重漂移。此原则的核心是约束输出格式和维度，这部分不会失败。

五、持续对齐与代偿机制
5.1 分布对齐
理论：随着新数据持续输入，更新生成模型对分布密度的估计。

工程可行性：中度风险。

✅ 在线更新方法（如增量聚类、在线归一化流）已存在。

⚠️ 风险：灾难性遗忘。增量更新可能导致旧分布被覆盖。

⚠️ 风险：更新频率与生成任务并行的计算负载。

备选路径（与记忆策略联动）：

使用原型压缩记忆（旧数据存储为聚类统计量+少量锚定样本），每次更新用核心集回放。

若算力不足：降频为批量更新（如每天一次），而非实时流式更新。

5.2 代偿机制
理论：检测到漂移时，核心模型冻结，启动代偿模型在隔离通道生成。

工程可行性：可行。

✅ 漂移检测（MMD/KS检验）是成熟方法。

✅ 双通道生成和标记是纯工程问题。

⚠️ 风险：漂移检测的阈值设定——太敏感导致频繁冻结，太迟钝导致漂移被漏掉。

备选路径：

阈值设为保守值（宁可迟钝一点，不频繁打扰用户），但记录漂移分数的时间序列供用户回溯审计。

用户可手动触发代偿启动，不强制自动。

能力漂移：若代偿机制中漂移检测不理想，系统回退为：每次模型更新时保存旧版本，用户手动对比和选择版本生成。

5.3 记忆策略
状态：五类策略（采样保留、原型压缩、权重巩固、生命周期、外部锚定）已完成理论定义，等待工程细化。目前无显著可行性风险，各策略均有现有方法支撑。

六、失败模式
失败模式	严重程度	行为	工程可行性
基准冲突	硬拒绝	不生成，返回冲突报告	✅ 纯校验逻辑，零风险
约束真空	降级	生成但标记未验证	✅ 条件检查+标记，低风险
模仿崩溃	自动回退	切换纯物理驱动	⚠️ 崩溃检测需要自适应阈值，初期可能需要人工设定，但核心逻辑可行
检测标准细化建议（交给工程团队）：

方差坍缩：生成数据的逐维方差 < 训练数据的同维方差的 ε（ε待实验确定，建议初始值0.1）。

模式坍缩：聚类后，生成数据的有效簇数 < 训练数据区有效簇数的 δ（δ待实验确定）。

过拟合噪声：生成样本与最近训练样本的平均距离 < 阈值。

七、与 Polymorphic-Twin 的关系
理论：两个独立系统，通过 EvidencePackage 协议协作。

工程可行性：完全可行。

✅ 标准接口设计是纯工程问题。

✅ 反馈隔离在信息论层面成立，不需要额外的加密或差分隐私机制（除非部署在极高安全要求环境，那是部署问题而非产品理论问题）。

八、理论公式（最终版）
SynthGen Core = 输入诚实性声明 + 物理合法性保证（有条件可行） + 统计逼真性贡献（有条件可行） + 可追溯性保证 + 持续对齐能力（含代偿） + 失败模式降级体系

可行性子项：

物理合法性：依赖约束卡片的质量（可工程化，但需专家输入）

统计逼真性：依赖数据量（可工程化，但小样本下退化）

约束驱动进阶方案：高风险，建议分阶段实施，基线方案（后筛选）可行

其余：完全可行

九、理论失败的总回退路径
如果上述理论框架中的核心假设被工程实践证伪，整个 SynthGen Core 不会完全报废，而是沿着以下路径逐步退化：

退化阶段	保留的能力	丧失的能力	仍可服务的场景
完整功能	全部	无	所有场景
约束驱动进阶不可用	物理合法性（纯物理驱动+后筛选）、统计逼真性（数据驱动）	高效的约束-数据融合	生成效率降低，但仍可产出合法数据
数据驱动不稳定（小样本）	物理合法性、可追溯性	统计逼真性	纯物理仿真场景（有专家约束卡片的场景）
物理约束缺失（无领域专家）	数据驱动（若有足够数据）、可追溯性	物理合法性保证	非安全关键场景的统计模拟
仅剩格式转换	可追溯性、格式合规	物理合法性、统计逼真性	数据格式标准化工具
完全不可用	无	全部	产品失败
这意味着：产品的核心设计是逐层可剥离的。每一个高风险模块被剥离后，剩余模块仍然构成一个可使用的、边界清晰的降级产品。这不是理论上的自我安慰，而是工程上的风险对冲。

十、对后续工程团队的移交说明
理论的哪些部分是确定的：输入诚实性、可追溯性、失败模式中的基准冲突和约束真空、与外部验证端的解耦关系。

哪些部分需要在工程中验证：数据驱动在小样本下的质量阈值、约束驱动的训练稳定性、模仿崩溃的精确检测阈值、漂移检测的最优灵敏度。

哪些部分可以推迟：记忆策略的具体算法选择、代偿机制的用户交互细节、约束驱动的进阶方案。

理论边界：本文档不声称 SynthGen Core 生成的数据是“可信”的。任何要求它自证可信的需求，超出了本理论框架的范围。
