攻击一回应：核心矛盾重新定义
原表述："数据生成器无法自证可信性"
审查意见：这是稻草人。所有生成模型都不自证可信。真正的矛盾是——当物理约束与数据分布在生成中产生张力时，多样性向哪个方向妥协？
裁定：🔴 接受。核心矛盾必须重新定义。
修订后的核心矛盾：
SynthGen Core 的根本矛盾不在于"无法自证可信"（此为所有生成模型共性），而在于：物理驱动要求一切生成点落在约束边界内（安全），数据驱动要求生成分布忠实于观测分布（逼真），而这两个要求在多维空间的稀疏区域必然发生冲突。矛盾不是"可信不可信"，是"安全与逼真在中低密度区不可兼得"。
理论立场：
当物理合法性与统计逼真性在某个生成区域产生不可调和的冲突时，物理合法性优先。这不是工程选择，是理论定义：SynthGen Core 的第一身份是"物理合法数据生成器"，第二身份才是"统计逼真数据生成器"。
理由：
• 统计逼真性的丧失只会让生成数据"看起来不对"。
• 物理合法性的丧失会让生成数据在物理上不可能，下游模型的训练和验证基础被破坏。
• 用户可以在统计逼真性不足时通过增加真实数据来改善；但用户无法在物理合法性缺失时通过任何后处理来恢复。
此优先级的推论：
• 约束驱动（融合）中，后筛选是基线方案，不是因为工程简单，而是因为它是唯一能保证物理优先的方案。损失函数约束和架构嵌入在无法严格保证物理约束满足时，不得取代后筛选作为最终防线。

攻击三回应：输入诚实性的重新定义
原表述："输入诚实性"承诺输出忠实于输入的三重基准。
审查意见：🟠 接受。当前只保证了边缘分布和格式，未保证变量间的依赖结构（联合分布）。"诚实"一词名不副实，应降级或升级。
修订：
将"输入诚实性"拆分为两个层次的承诺：
层次一：输入格式忠实性（必须保证）
输出数据严格匹配输入数据定义的格式Schema和物理量维度集合。生成器绝不添加用户未批准的维度，绝不改变数据类型和结构。
此层次完全可行，不作任何妥协。
层次二：统计签名忠实性（尽力保证，明确不确定范围）
输出数据在以下统计层次上逼近输入数据的经验分布：
• 已保证：各维度的值域、单变量分布的低阶矩（均值、方差）
• 部分保证：双变量相关系数、自相关结构
• 不保证：高阶依赖关系、因果结构
用户必须被告知此层次的实际覆盖范围。EvidencePackage 中新增字段 statistical_fidelity: {guaranteed: [...], partial: [...], unguaranteed: [...]}，让用户明确知道自己在用什么。
此修订的理论意义：系统不再暗示它知道数据的完整联合分布，而是诚实声明自己对输入数据的统计理解到了什么层次。

区分标准（理论层面）：
演化与漂移的区分不能仅靠统计检验，因为它们在统计上可能完全相同（都是分布变化）。
区分逻辑：
1. 如果物理约束卡片定义了合法的稳态分布边界，且新数据仍在边界内 → 倾向于演化。
2. 如果新数据突破了物理约束边界，或出现了约束卡片中未定义的新模式 → 倾向于漂移（或新现象发现，需用户判断）。
3. 系统可以提供演化/漂移假设，但最终判定权在用户。系统不自动做出不可逆的模型合并决策。
代偿机制的修正：
• 冻结核心模型和启动代偿，仅在系统检测到漂移信号（违反约束或出现新模式）时触发。
• 对于边界内的渐进变化，系统进行持续适应（分布对齐），同时记录演化轨迹，定期向用户报告。
• 用户可随时切换演化/漂移判定的默认行为。

攻击六回应：失败模式阈值的理论论证
原表述："交给工程团队"。
审查意见：🟠 接受。必须给出每个阈值的理论论证，哪怕是粗糙的。
修订：检测阈值的理论依据
方差坍缩（ε）
理论依据：如果生成数据的方差低于训练数据方差的某个比例，说明生成器不再覆盖训练数据的分散性。
• 下限：ε = 0。此时系统仅在生成器输出常数时触发。理论上不会误报，但可能严重漏报。
• 上限：ε = 1。此时系统要求生成数据方差不低于训练数据方差，任何时候都触发，不实用。
• 理论推荐：ε = 0.1。理由——当生成数据的方差不到训练数据的1/10时，生成器已经不是在"模仿分布"而是在"复述均值的精确副本"。这种程度的坍缩在GAN训练中是公认的失败信号（Goodfellow et al., 2014；Arjovsky & Bottou, 2017）。
• 工程确认：需要在实际工业数据集上验证ε=0.1是否可以提供足够的预警，但不低于0.01（低于0.01将接近零方差，失去检测意义）。
模式坍缩（δ）
理论依据：如果生成数据只覆盖了训练数据中少数几个簇，生成器失去了多样性。
• 下限：δ = 0。此时系统仅在生成数据坍缩到一个簇时触发。
• 上限：δ = 训练数据有效簇数。此时系统要求生成数据覆盖每一个簇，可能过于苛刻（某些小簇可能是噪声）。
• 理论推荐：δ = 训练数据有效簇数的1/2（向上取整至少为2）。理由——如果生成数据覆盖的簇数不到训练数据簇数的一半，说明生成器丢失了大量模式。这个比例在模式坍缩文献中被接受为有效性阈值（Metz et al., 2017）。
• 工程确认：需要在实际数据集上用聚类算法验证簇数估计的稳定性。
过拟合噪声（距离阈值）
理论依据：如果生成样本与最近训练样本的平均距离低于某个阈值，说明生成器在复制训练数据。
• 理论推荐：距离阈值 = 训练数据内部最近邻平均距离的1/2。理由——如果生成样本与训练样本的距离，小于训练样本之间的典型距离，说明生成样本没有带来新信息，是在过拟合而非泛化。
声明：
这些阈值有理论依据支撑，但具体的数值选择需要在工程实现中校准。理论框架确定了阈值的合理范围和校准原则，工程团队的责任是确定具体数值，而非从零论证其合理性。

约束缺失时的强制行为：
• 系统必须在 EvidencePackage 中将数据等级标记为 data_grade: physics_unguaranteed
• 用户界面必须在生成前弹窗警告，要求用户确认
• 如果系统对接 Polymorphic-Twin，Core 应在检疫时拒绝 physics_unguaranteed 等级的数据进入 shadow 及以上链路，除非用户显式豁免
此修订的理论意义：
SynthGen Core 不再假装约束缺失只是"功能退化"。这是一个明确定义的身份切换——它变成了另一个产品。这是对用户和工程团队的诚实交代。
修订后的理论公式
SynthGen Core = 格式忠实性保证 + 统计签名部分忠实声明 + 物理合法性优先（在物理约束完备时） + 可追溯性保证 + 持续对齐能力（区分演化与漂移） + 组合退化降级体系 + 约束缺失时的身份切换
与 v1.0 的核心差异：
1. 核心矛盾从"无法自证可信"重新定义为"安全与逼真不可兼得时的优先选择"
2. 输入诚实性拆分为两个层次，只保证格式，不假装保证因果结构
3. 退化路径从线性改为组合分析，增加最差场景专项分析
4. 代偿机制加入漂移/演化的理论区分
5. 反馈隔离从"信息论成立"收紧为"协议层面切断"
6. 失败模式阈值提供了理论论证
7. 约束缺失重新分级为身份切换而非单纯降级
