## 新发现的问题

### 问题一（🟡 中）：约束分类规则需显式声明

**位置**：3.3

**问题**：编译分类逻辑说"识别所有值域约束"、"识别所有行间约束"，但分类规则未声明。`temperature > -40 WHEN wind_speed > 20` 是值域还是行间？靠语义推断不如靠语法规则。

**建议**：在 3.3 增加显式分类规则：

```
分类规则：
- 含时序索引 [t] 或 [t-N] → 行间约束
- 含聚合函数 (AVG/SUM/COUNT/...) + OVER → 聚合约束
- 其他 → 值域约束
```

Parser 可机械执行，无需语义推断。

---

### 问题二（🟡 中）：atomic_write 隔离级别未声明

**位置**：5.1, 5.2

**问题**：并发 GENERATE 写入 + GC compaction 的隔离保证未声明。

**建议**：声明 v1 隔离级别（建议 Read Committed），声明 GC 事务边界与读写操作的并发控制。

---

### 问题三（🟢 低）：ORDER 多列排序

**位置**：2.2

**问题**：当前只有单列 ORDER。多列排序（如先 device_id 再 timestamp）无法表达。v1 不需支持，但可预留语法。

---

### 问题四（🟢 低）：增量对齐 data_origin 传递

**位置**：2.2, 第七节

**问题**：`UPDATE GENERATION MODEL ... INCORPORATE DATA FROM sensor_log` 是否继承 data_origin 标记？混合来源的基表在增量对齐时 provenance 粒度可能不够。

**建议**：声明 `INCORPORATE DATA` 继承 `LOAD DATA` 的 data_origin 标记。
