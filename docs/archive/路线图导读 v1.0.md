SynthGen Core 路线图导读 v1.0
为什么选择能力里程碑路线？
日期：2026-05-10

---

## 一句话

从自行车到跑车，每个阶段都能骑，每个阶段都更快。

---

## 核心隐喻

想象你造一台车：

❌ **水平分层法**：先造完所有轮子，再造完所有发动机，再装所有车身，最后组装——前三个月你连车都看不到，只能看一堆零件。

❌ **垂直切片法**：先造一辆能跑的三轮车，再改装成四轮，再加发动机，再加空调——每次改装都要拆了重来，接口不断变。

✅ **能力里程碑法**：

```
v1 自行车    → 能骑，能到目的地，验证了"人能在这上面走"
v2 摩托车    → 有引擎，跑得快，验证了"动力系统可靠"
v3 轿车      → 有空调有导航，验证了"舒适性和智能化"
v4 跑车      → 极致性能，验证了"边界条件下依然可控"
```

每个阶段**完整可用**，每个阶段**自然进化**到下一阶段，不需要拆了重来。

---

## 为什么不选水平分层？

水平分层看起来"架构清晰"——先把接口层做完，再把引擎做完，最后做存储。

问题：**前三个月没有任何可运行输出。**

你无法验证：
- Parser 解析出来的语法树，生成引擎能不能用
- 存储层写进去的格式，约束引擎能不能读
- EvidencePackage 的字段定义，SDK 用户觉得够不够

等你发现接口不对，已经写了三个月。改接口 = 改三层 = 重来。

能力里程碑不存在这个问题。v1 两周后你就能跑端到端：数据进去→约束过滤→证据包出来。接口不对？当时就发现，当时就改。

---

## 为什么不选垂直切片？

垂直切片看起来"最快出活"——先做一个最小切片，逐步扩展。

问题：**早期切片的接口在扩展时要重构。**

比如第一刀切"只支持整数类型"，第二刀扩展浮点数，第三刀加时间类型——每次都要改 Parser、改存储、改引擎。改了三轮，最初的代码面目全非。

能力里程碑不存在这个问题。v1 的值域约束引擎在 v2 不需要重构——v2 只是在旁边加了行间引擎和聚合引擎，值域引擎原封不动。因为理论框架 v1.3 已经定义了三类约束的分层关系，我们在 v1 就按分层设计，只是只实现第一层。

**先有理论，后有路线。理论已经告诉你分层是什么，路线就按分层走。**

---

## 为什么是这四个版本？

不是拍脑袋分的。是理论框架 v1.3 的约束分层决定的：

```
理论层          →  路线图版本
─────────────────────────────
值域约束（逐行）  →  v1 最小可运行
行间约束（有状态）→  v2 约束完整（加上行间+聚合）
聚合约束（两阶段）→  v2 约束完整（与行间同版本，因为阶段一包含行间）
─────────────────────────────
时间维度         →  v3 时间智能
窗口扩展+完备度  →  v4 高级分析
```

关键洞察：**聚合约束的两阶段执行中，阶段一就是值域+行间**。所以聚合约束不能脱离行间约束单独实现。它们天然属于同一个版本（v2）。

这不是我决定的，是数学决定的。

---

## 每个版本的"车"能做什么

### v1 自行车

- 定义数据长什么样（Schema）
- 把真实数据搬进来（LOAD DATA）
- 告诉系统"温度不能超过80度"（值域约束）
- 拿到合规数据和证据包（GENERATE TABLE + EvidencePackage）

**能骑了**。虽然只有单速，但你能从A到B。

### v2 摩托车

- 行间约束：相邻两行温度差不能超过5度
- 聚合约束：1小时内平均温度不能超过40度
- 退化路径：数据不够？自动降级到物理引擎
- 审计日志：每一步操作都有哈希链可追溯

**有引擎了**。不只能骑，还能在复杂地形上跑。

### v3 轿车

- 时间旅行：回到旧版本看看当时的生成结果
- 持续对齐：新数据来了，模型自动进化
- 模型版本管理：旧版本自动合并，但元数据保留
- tail_report：告诉你生成的数据有多少可信度

**有导航和空调了**。不只是跑，还知道跑过哪里，跑到哪里去。

### v4 跑车

- 行数窗口/分组窗口/会话窗口：任意切法
- 约束完备度评分：0.0-1.0，不再是"有/没有"
- 反例搜索：自动找出数据的盲区

**极致性能和洞察**。不只是跑得快，还能看到看不见的。

---

## 为什么 v1 选"最小可运行"而不是"约束完整"？

因为自行车比摩托车更早能骑。

v1 只做值域约束，5-6周就能看到端到端输出。如果 v1 就做三类约束，周期翻倍，前10周没有任何可演示成果。

更重要的是：**v1 的值域约束是 v2 聚合约束阶段一的基础**。没有值域约束，聚合约束的两阶段执行无从谈起。先造轮子（值域），再装发动机（行间+聚合），顺序不能反。

---

## 总结

路线图的选择逻辑，就三条：

1. **每个阶段都能骑**——端到端可运行，不是零件堆
2. **每个阶段自然进化**——不拆了重来，前阶段的产出是后阶段的基础
3. **分层由理论决定**——不是拍脑袋，是约束的数学结构决定了版本边界

自行车→摩托车→轿车→跑车。

每一步都能上路，每一步都比上一步强。
