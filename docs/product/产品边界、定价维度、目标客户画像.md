一、产品边界
1.1 SynthGen Core 是什么
维度	定义
一句话定位	面向工业AI的智能合成数据引擎
核心交付	输入场景需求 → 输出带标注、可追溯、物理自检的高质量模拟数据集
产品形态	本地部署的软件套件（核心引擎 + CLI/API + 可选Web控制台）
用户角色	数据工程师、ML工程师、仿真工程师、领域专家
1.2 SynthGen Core 做什么
接收自然语言或结构化spec作为场景描述

基于物理引擎和/或数据驱动生成器，生成多模态仿真数据

自动为所有生成数据附加精确真值标注

内嵌物理约束自检，过滤明显违反物理定律的样本

输出标准EvidencePackage格式，可对接Polymorphic-Twin的Core检疫

记录完整provenance（参数、种子、生成器版本），保证可复现

支持反例搜索模式：主动寻找使目标模型失效的数据点

1.3 SynthGen Core 明确不做什么
不替代高保真物理仿真器（不声称达到ANSYS/COMSOL精度）

不判断生成数据是否可以用于生产决策（那是Polymorphic-Twin的职责）

不管理ML训练流程（不调参、不部署模型）

不接入实时生产数据流

不是数据标注平台（不做人工标注管理）

不开箱即用（需要用户提供场景描述和基本物理参数）

二、目标客户画像
2.1 第一梯队：工业AI团队（核心客户）
典型画像：

所属行业：先进制造、能源、自动驾驶、机器人、航空航天

团队规模：10-100人的AI/ML团队

核心痛点：真实故障数据稀缺、数据标注成本高、边缘场景覆盖不足、物理测试昂贵且危险

使用场景：

训练故障预测模型，但只有少量真实故障案例

需要覆盖极端工况（台风、地震、设备老化组合），但无法在真实设备上测试

需要在部署前验证模型的安全边界

需要向监管方证明模型经过了充分的边缘场景测试

为什么选SynthGen Core而不是自建：

自建仿真数据管道工程量大，且难以保证数据一致性

缺乏内嵌的物理自检能力，自建容易产出“物理上不可能”的脏数据

需要可追溯的provenance，这是自建脚本往往忽略的

2.2 第二梯队：工业设备制造商（增值客户）
典型画像：

制造风机、燃气轮机、工业机器人、精密机床的企业

已经拥有物理仿真能力（有ANSYS/Simulink团队）

核心痛点：仿真团队产出的数据量不足以支撑AI训练，传统仿真运行太慢，无法覆盖参数空间

使用场景：

将少量高保真仿真结果作为“种子”，用SynthGen Core的数据驱动增强模块，生成大量变体

利用反例搜索功能，向客户（设备使用者）交付“已知失效边界已探索”的证明

为什么选SynthGen Core：

不替代ANSYS，而是在其基础上做规模化增值

提供了仿真团队不擅长的AI增强和结构化数据管理能力

2.3 第三梯队：独立软件供应商（生态客户）
典型画像：

开发工业AI应用（预测性维护、视觉检测、自主控制）的ISV

核心痛点：每个项目都要从头搭建数据生成管道，项目交付周期长，数据质量参差不齐

使用场景：

将SynthGen Core嵌入自己的产品栈，作为标准化数据生成模块

为不同行业客户快速生成特定场景的训练数据

为什么选SynthGen Core：

缩短交付周期，降低数据工程成本

提供标准化输出，减少集成风险

可选搭配Polymorphic-Twin，为客户提供“生成+治理”完整方案

2.4 非目标客户（需要明确排除）
纯学术研究团队（无付费意愿，应走开源社区路线）

只需要通用表格/文本合成数据的企业（市场上有更轻量的竞品，如Gretel、Tonic.ai）

期望“输入产品手册就出AI模型”的客户（产品门槛高于他们预期）

三、定价维度建议
3.1 核心定价逻辑
按生成数据价值定价，而非按计算资源定价。

原因是：

客户关心的是“我获得了多少可用的训练/测试数据”，而非“用了多少GPU小时”

按计算资源定价会让客户刻意减少生成量，违背产品价值主张

按数据价值定价，客户的目标是“最大化可入库的数据量”，与产品价值一致

3.2 建议定价维度
维度	单位	说明
基础许可费	年费	软件使用权，含基础功能（结构化spec生成、物理引擎后端、标准导出）
场景数量	每个DomainPack	不同工业场景需要单独配置（如“风电叶片结冰”vs“燃气轮机燃烧不稳定”），按激活的场景数计费
高级后端	每个后端/年	PINN生成器、LLM编译器、反例搜索模块作为可选高级功能单独计费
生成数据量阶梯	每百万样本点	基础许可含一定额度，超出后按阶梯计费，量大从优
企业支持	年费	SLA、专属支持、自定义开发、合规文档
3.3 不推荐的定价方式（及原因）
方式	不推荐原因
按GPU小时	驱动错误行为：客户减少生成量，产品价值被抑制
按用户数	不利于团队内推广，客户采购阻力大
按生成器调用次数	难以预测客户成本，阻碍长期合同
一次性买断	产品持续迭代（新场景、新后端），一次性不符合双方利益
按数据导出的量	客户可能因为成本而不导出数据，产品价值无法兑现
3.4 许可证层级建议
等级	面向	包含
Starter	小型AI团队/PoC	基础引擎 + 1个DomainPack + 物理仿真后端 + 标准导出
Professional	中等规模ML工程团队	+ 多DomainPack + PINN生成器 + 反例搜索 + EvidencePackage导出
Enterprise	大型企业/SV	+ LLM编译器 + 专属场景定制 + 本地化部署 + 审计合规包
3.5 开放式可选的增值服务
场景定制服务：帮助客户创建专属DomainPack（一次性工程服务费）

合规认证包：针对特定行业（如航空DO-178C、医疗FDA）的文档和验证支持

联合推向市场：对ISV客户，提供共同品牌方案和收入分成模式

四、竞争壁垒简述
壁垒类型	具体形式
技术壁垒	物理约束自检引擎、可插拔生成器架构、provenance追踪系统
