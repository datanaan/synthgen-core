一、系统定位
SynthGen Core 是一个面向物理世界的智能合成数据生成器。其根本使命：

在用户给定的数据世界框架内，生成其可能存在样貌的多样性。

系统身份：SynthGen Core 是一个独立产品，不与任何特定治理平台绑定。它以标准化数据包协议对外交付产物，可选地与可信治理基础设施（如 Polymorphic-Twin）协作，但两者的理论地位完全解耦。

系统边界：

SynthGen Core 负责：在已知物理边界和用户输入格式内，生产可追溯的候选数据集。

SynthGen Core 不负责：判定所生成数据的最终可信性，也不替代高保真物理仿真器或机器学习训练平台。

二、核心矛盾与理论立场
2.1 核心矛盾
SynthGen Core 的根本矛盾在于：物理驱动要求一切生成点落在约束边界内（安全），数据驱动要求生成分布忠实于观测分布（逼真），而这两个要求在多维空间的稀疏区域必然发生冲突。矛盾不是"可信不可信"，是"安全与逼真在中低密度区不可兼得"。

此矛盾并非 SynthGen Core 独有，而是所有面向物理世界的合成数据生成器必须面对的结构性张力。不承认此矛盾的系统，必然在安全关键场景中失效。

2.2 理论立场：物理优先
当物理合法性与统计逼真性在某个生成区域产生不可调和的冲突时，物理合法性优先。SynthGen Core 的第一身份是"物理合法数据生成器"，第二身份才是"统计逼真数据生成器"。

理由：

统计逼真性的丧失只会让生成数据"看起来不对"，用户可以通过增加真实数据来改善。

物理合法性的丧失会让生成数据在物理上不可能，下游模型的训练和验证基础被破坏，且无法通过任何后处理恢复。

安全关键应用不能容忍物理上不可能的数据被用于训练或验证。

此优先级的工程推论：

约束驱动（融合）中，后筛选是基线方案，不是因为工程简单，而是因为它是唯一能严格保证物理优先的方案。

损失函数约束和架构嵌入在无法严格保证物理约束满足时，不得取代后筛选作为最终防线。

2.3 物理优先的认识论偏差声明
物理优先是一个经过理论审视的选择，而非价值中立的优化。它会产生一项可预见的系统性偏差：生成数据世界的尾部风险谱比真实物理世界更窄。落在约束边界外侧的罕见但真实的事件，可能被系统性地排除或降级标记。

这不是理论的缺陷，而是物理优先选择的必然推论。 理论框架的责任不是消除这个偏差（无法消除），而是确保它被明确声明，并在 EvidencePackage 中提供可量化的偏差报告，让下游使用者在知情的前提下做出决策。

三、三大能力支柱
SynthGen Core 的理论能力建立在三个互补的支柱之上。三者分工明确，互不越界。

支柱	核心问题	技术路径	保证的维度	工程可行性
物理驱动	这个数据点是否物理合法？	领域约束卡片、物理仿真引擎、解析模型	物理合法性	有条件可行（需约束卡片质量）
数据驱动	这个数据点是否"像真的"？	GAN、VAE、扩散模型、KDE扰动	统计逼真性	有条件可行（需数据量支持）
约束驱动（融合）	如何让模仿过程不越界？	逐行过滤、有状态过滤、两阶段窗口验证	受控的逼真性	按约束类型分路径实施
3.1 物理驱动
理论：在约束卡片定义的合法空间内生成数据点。

工程可行性评估：

约束卡片是领域专家可编写的声明式规则，工程可实现。

风险：约束卡片的编写需要领域专家。若无专家，此支柱退化。

风险：约束卡片可能存在遗漏或内部冲突。系统需要冲突检测和缺失告警。

备选路径：

若无领域专家：使用统计方法从数据中估计值域，但明确标记为"统计推断边界，非物理边界"。

若约束卡片冲突：系统检测并报告，允许用户手动解决，拒绝在冲突约束下生成。

3.2 数据驱动（模仿）
理论：从真实数据中学习分布，生成统计上相似的数据。

工程可行性评估：

对于结构化时序数据，GAN/VAE/扩散模型已在多个工业领域验证。

风险：小样本问题。当真实数据少于几百条时，生成质量急剧下降。

风险：高维稀疏数据。维度很多但每个维度的有效样本很少。

备选路径：

小样本：退化为基于KDE的扰动生成，比神经网络粗糙但不会坍缩。

高维稀疏：先做维度重要性筛选或主成分分析，在低维隐空间生成，再映射回原始维度。

极端情况：回退为纯物理驱动（见失败模式三）。

3.3 约束驱动（融合）
理论：在数据驱动生成过程中施加物理约束，实现受控的逼真性。约束驱动的核心是约束类型决定验证路径。

3.3.1 约束的三类理论分层
物理约束在验证时表现为三种不同的语义类型，它们不是工程细节，而是理论上的本质区分：

约束类型	定义	示例	验证模型	理论特征
值域约束	单数据点的独立合法范围	wind_speed ∈ [0, 25]	逐点检查	无状态，与其他行无关
行间约束	数据点之间的时序或结构依赖	vibration[t] − vibration[t−1] < 5.0	有状态检查，需要排序和帧缓冲	有序性依赖，需要排序列定义
聚合约束	数据窗口的统计量约束	AVG(temperature) OVER 1 HOUR ≤ 40.0	两阶段执行：先逐点过滤值域/行间约束，再窗口聚合验证	改变验证粒度（从行到窗口），改变排除率语义
三类约束的优先级：值域约束是最底层约束。在任何执行路径中，值域约束必须最先执行，不可被跳过。行间约束次之，聚合约束最后。

3.3.2 聚合约束的理论特殊性
聚合约束与值域约束和行间约束有本质区别，其引入改变了生成验证的理论模型：

验证粒度变化：值域约束和行间约束以行为单位进行验证——某行违反约束，该行被排除。聚合约束以窗口为单位进行验证——某个窗口违反约束，窗口内所有行被排除。

排除率语义变化：

在仅含值域约束和行间约束的生成中，排除率 = 被排除的行数 / 总生成行数。

在含聚合约束的生成中，排除率 = 被排除的窗口数 / 总窗口数 × 窗口内行数 / 总生成行数。排除率的含义从"行级抛弃率"变为"窗口级抛弃率"。

因此，聚合约束的存在影响 tail_report 的排除率报告维度，需要单独标注。

两阶段执行的不可合并性：聚合约束不能与值域约束/行间约束在同一个逐行过滤流程中合并执行。它必须在所有值域约束和行间约束执行完毕后，在窗口聚合层单独执行。任何试图将聚合约束"降级"为逐行约束的尝试，都会改变约束语义（例如，AVG ≤ 40 不能等价于任何单行条件）。

3.3.3 约束融合的技术路径
阶段	方案	可行性	说明
第一阶段（基线）	后筛选	✅ 可行	按约束类型分层执行过滤，是唯一能严格保证物理优先的方案
第二阶段（进阶）	损失函数正则化（PINN-GAN等）	⚠️ 高风险	训练不稳定，超参数敏感，属活跃研究领域
第三阶段（远期）	架构嵌入	⚠️ 高风险	每类约束需单独设计，通用性差，待研究成熟
阶段间关系：后筛选是最终防线。进阶方案在无法严格保证物理约束满足时，不得取代后筛选。

四、输入诚实性
输入诚实性拆分为两个层次，各自有明确的理论承诺范围。

4.1 层次一：输入格式忠实性（必须保证，不可降级）
输出数据严格匹配输入数据定义的格式Schema和物理量维度集合。生成器绝不添加用户未批准的维度，绝不改变数据类型和结构。

工程可行性：完全可行。纯校验逻辑，零风险。

4.2 层次二：统计签名忠实性（条件保证+误差界）
输出数据在以下统计层次上逼近输入数据的经验分布。每个层次的保证有明确的生效条件和误差界。

保证层次	覆盖内容	生效条件	误差界
无条件保证	各维度值域、均值、方差	无	精确匹配
条件保证	双变量相关系数	训练数据量 ≥ 维度数 × 10	相关系数绝对误差 < 0.2
条件保证	自相关结构	时序长度 ≥ 最低周期 × 5	自相关峰值偏移 ≤ 1 lag
不保证	高阶依赖关系、因果结构	—	明确声明不可用
EvidencePackage 中新增字段 statistical_fidelity，声明各层次的覆盖范围、生效条件是否满足、以及实测误差。若条件未满足，相应层次自动标记为 not_guaranteed。

4.3 基准协商
用户输入定义了输出基准。若用户请求的生成规格超出了输入数据定义的维度或格式，系统进入失败模式一（基准冲突）。

若系统识别到输入数据的维度可能不足以充分描述场景，系统可在任务启动时向用户呈现可选扩展维度的建议。任何扩展必须经过用户显式批准，禁止系统自主添加用户未批准的维度。

五、持续对齐与代偿机制
5.1 分布对齐
理论：随着新数据持续输入，更新生成模型对分布密度的估计。

工程可行性：中度风险。增量更新方法已存在，但需应对灾难性遗忘和计算负载。

与记忆策略联动：使用原型压缩记忆和核心集回放对抗灾难性遗忘。算力不足时降频为批量更新。

5.2 漂移与演化的理论区分
必须区分两种性质不同的分布变化：

概念	定义	系统行为	用户确认需求
分布演化	基础物理过程本身变化（设备老化、气候变化）。旧分布逐渐失效，新分布成为新常态。	不冻结核心模型，持续适应。记录演化轨迹，定期报告。	被告知演化趋势，但不阻断自动适应
分布漂移	数据生成过程出现异常（传感器故障、操作错误）。旧分布仍然合法，新数据是暂时性偏离。	冻结核心模型，启动代偿隔离通道。	必须确认漂移性质后才能收束
区分标准——与系统身份联动：

漂移检测的标准必须与系统当前的约束完备性身份联动，避免循环依赖：

系统身份	data_grade	漂移检测模式	判定标准
物理合法数据生成器	physics_guaranteed	联合模式	物理约束边界 + 统计检验（MMD/KS）联合判定
统计相似数据生成器	physics_unguaranteed	纯统计模式	仅MMD/KS检验 + 滑动窗口分布比较。声明：drift_detection_mode: statistics_only, constraint_unavailable: true
格式化扰动生成器	physics_unguaranteed	不可用	系统信息量不足以区分漂移与演化。声明：drift_detection: unavailable
此联动确保：当约束缺席时，漂移检测不会继续依赖一个不存在的判定基准。

5.3 代偿机制
触发条件：系统检测到漂移信号时（在联合模式或纯统计模式下）。

步骤：

核心生成模型冻结，不再更新。

新建代偿生成器子模型，仅用最近漂移数据训练。

双通道生成：核心通道产出标记 distribution_basis: core，代偿通道产出标记 distribution_basis: compensatory + drift_detected: true。

用户根据漂移性质做出判断，系统据此收束（合并/保留为条件分支/废弃）。

若用户未在可配置的时限内做出判断，代偿通道继续运行，但系统定期提示未关闭的漂移事件。代偿模型受模型版本GC策略管理，过期后自动标记但暂不物理删除，直至用户做出判断。

关键约束：代偿模型运行在与核心模型相同的参数空间和约束卡片体系内，不独立扩展物理边界。

5.4 新数据的来源边界
允许进入持续对齐的数据：

用户从生产系统直接提供的原始传感器数据

用户从独立测试台或实验采集的数据

公开或行业标准数据集

历史归档数据

禁止进入持续对齐的数据：

包含第三方系统验证结论的衍生数据

由 SynthGen Core 生成、经外部审判后回流的数据

人类操作者基于外部验证结果做出的修正数据

检测机制：所有进入持续对齐的数据必须携带溯源标记 data_origin。系统在接收时检查此字段，若属于禁止类别，硬拒绝用于分布对齐。

六、失败模式的形式化定义
SynthGen Core 的失败不是系统崩溃，而是：

系统识别到自身无法在当前条件下履行"生成符合理论声明的候选数据"这一职责，并据此采取预定义的降级行为。

6.1 失败模式一：基准冲突
定义：用户请求的生成规格，超出了用户输入数据所定义的三重基准（格式、维度、可行性暗示）。

检测标准：

请求包含输入数据中不存在的物理量维度

请求的值域超出输入数据暗示的范围，且超出约束卡片覆盖范围

请求的数据格式与输入数据定义的格式不同

系统行为：

硬拒绝，不生成任何数据。

返回基准冲突报告，精确列出冲突项和建议解决路径。

严重程度：硬拒绝。违反格式忠实性，无降级产出。

6.2 失败模式二：约束真空
定义：用户请求的生成参数空间，在已有约束卡片中找不到对应覆盖。系统无法判定该区域的物理合法性。

检测标准：请求的参数空间与已加载约束卡片的适用域有间隙，间隙内物理合法性不可判定。

系统行为：

仍生成数据，但降级标记。

EvidencePackage 中标记 generation_status: degraded、degradation_reason: constraint_vacuum、unverified_parameters: [...]。

约束自检报告显示为"未检定"而非"通过"，并附带声明：caveat: 此数据未经过物理约束验证，可能违反未知的物理定律。

严重程度：降级。产出有效性保留但物理合法性未知。

6.3 失败模式三：模仿崩溃
定义：真实数据量过少或分布极度单一，导致数据驱动生成器无法学习有意义的分布。

检测标准（至少触发其一）：

检测项	阈值	理论依据
方差坍缩	生成数据方差 < 训练数据方差 × 0.1	方差坍缩作为GAN训练失败信号已有文献支撑。ε=0.1是基于工程经验的推荐值——当生成数据方差不到训练数据的1/10时，生成器已实质性地退化为均值复制器。具体数值需在工业数据集上校准
模式坍缩	生成数据有效簇数 < 训练数据有效簇数 × 1/2	覆盖不足一半时，大量模式丢失
过拟合噪声	生成样本与最近训练样本平均距离 < 训练数据内部最近邻平均距离 × 1/2	比训练样本间距离还小，说明无新信息，在复制而非泛化
数据量不足	训练数据量低于自适应阈值	维度的倍数或绝对数量不足
物理约束排除率	后筛选排除比例 > 0.9	当超过90%的生成样本被物理约束排除时，生成-过滤流水线退化为拒绝采样。此阈值标志着数据驱动模型与物理约束空间严重不匹配
系统行为：

自动切换为纯物理驱动模式。

EvidencePackage 中标记：generation_mode: fallback_physics_only、data_driven_disabled: true。

不尝试重新训练数据驱动模型，避免不稳定循环。等待更多真实数据到达或用户手动解除。

若触发的是物理约束排除率阈值，额外警告用户检查约束卡片是否过严或数据驱动模型是否需要重新训练。

严重程度：自动回退。产出仅保证物理合法性，统计逼真性丧失。

6.4 尾部裁剪报告
物理优先选择会系统性压缩生成数据世界的尾部风险。为履行认识论偏差声明（2.3节）的诚实义务，EvidencePackage 中必须包含尾部裁剪报告：

conservative_tail_report 字段结构：

子字段	内容	用途
excluded_by_physics_ratio	被物理约束排除的生成样本比例（相对总生成量）	量化裁剪程度
excluded_region_features	排除区域的分布特征摘要：均值、方差，与被保留区域的KL散度	让用户知道被裁剪掉的是什么
constraint_type_breakdown	按约束类型（值域/行间/聚合）分别统计排除率	区分不同类型约束的裁剪贡献
aggregation_window_discard_rate	仅含聚合约束时：被丢弃的窗口占比	含聚合约束时，排除率按窗口维度单独报告
tail_skew_assessment	定性评估：narrower_than_real_world / unknown	明确声明生成数据世界的风险结构偏差
disclaimer	此数据世界因物理优先选择而拥有比真实物理世界更窄的尾部风险谱。此偏差是理论选择的结果，非工程缺陷。用户有权在知情后自行判断数据用于下游任务的适宜性。	诚实声明

九、与 Polymorphic-Twin 的理论关系
9.1 协作定位
SynthGen Core：证据提供者（制造候选）。

Polymorphic-Twin 的 Core 组件：证据审判者（验证、定级、赋予链路权限）。

两者是独立系统，通过标准化 EvidencePackage 协议形成"生成-审判"协作。

9.2 反馈隔离的协议保证
SynthGen Core 不要求反馈隔离在密码学意义上成立。它要求的是——通过协议设计，在架构层面切断从验证结果到生成模型更新的数据通路。

具体措施：

新数据来源边界定义（见5.4节）在协议层面硬拒绝验证衍生数据回流。

部署层面的契约约束是隔离的第一道防线。

9.3 理论边界的刚性声明
任何绕过新数据来源边界协议的部署，不再是 SynthGen Core 理论框架覆盖的系统。其输出数据不享有本框架的任何理论保证，包括但不限于格式忠实性、可追溯性和身份声明的有效性。

协议不是建议，是定义。破坏协议就是退出框架。

十、最终理论公式
SynthGen Core = 格式忠实性保证 + 统计签名条件保证（含误差界） + 物理合法性优先（在物理约束完备时） + 约束类型分层（值域/行间/聚合） + 认识论偏差声明 + 可追溯性保证 + 持续对齐能力（区分演化与漂移，漂移检测与身份联动） + 组合退化降级体系（附概率标注） + 约束缺失时的身份切换与服务分级

各子项能力边界：

格式忠实性：必须保证，不可降级。

统计签名忠实性：无条件保证值域和低阶矩；在满足数据量条件时条件保证双变量相关和自相关结构（附误差界）；明确不保证高阶依赖和因果结构。

物理合法性：在约束完备时优先于统计逼真性。约束缺失时系统身份切换，此保证失效。物理合法性由值域约束、行间约束和聚合约束分层执行验证，聚合约束的引入改变了排除率的计算维度。

认识论偏差：物理优先导致生成数据世界比真实世界更安全——此偏差已声明，非隐藏缺陷。尾部裁剪报告按约束类型分解排除率。

可追溯性：全生成链路记录，含模型版本链，不可降级。

持续对齐：区分演化与漂移；漂移检测模式与约束完备性身份联动；新数据来源受协议边界硬约束。代偿机制含收敛时限。

降级体系：组合退化，附定性概率排序；最坏场景系统退化为格式转换工具。

身份切换：约束缺失时系统从"物理合法数据生成器"切换为"统计相似数据生成器"；安全关键场景硬拒绝不可豁免。
